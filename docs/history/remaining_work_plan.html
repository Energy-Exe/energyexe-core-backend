2. P1 ERA5 NaN wind data — root cause & fix

2.1 What we found

Two production import paths exist with inconsistent bounding‑box (bbox) handling:

PathBboxUsed by
app/core/weather_import.py:249Hardcoded Europe [71, −11, 35, 32]WeatherImportService.execute_job() → POST /weather-imports/*
scripts/seeds/weather_data/fetch_daily_all_windfarms.py:87–92Dynamic from windfarm coords (max±0.5°)WeatherDataService → POST /weather-data/fetch

2.2 The bug chain

  1. cdsapi.Client.retrieve(...) requests a GRIB only over Europe.
  2. For a US/Taiwan windfarm, xarray.interp(method='linear') on a coordinate outside the bbox returns NaN.
  3. float(NaN) propagates without raising. math.sqrt(NaN**2 + NaN**2) = NaN. round(NaN, 3) = NaN.
  4. The model column is wind_speed_100m: Numeric(8, 3), nullable=False. nullable=False only blocks NULL — PostgreSQL numeric accepts NaN as a valid value, so the row inserts cleanly.
  5. Downstream queries use WHERE wind_speed_100m IS NOT NULL which doesn't catch NaN. The pandas pipeline filters NaN out and ends with zero usable hours per windfarm.

2.4 Code fixes (3 changes, scoped to app/core/weather_import.py + the daily script)

Fix A — Replace hardcoded Europe bbox with dynamic bbox

Extract a shared helper to avoid the same bug from recurring through duplication.

# app/core/weather_import.py — new helper
async def _compute_windfarm_bbox(self) -> List[float]:
    """Return [N, W, S, E] covering all active windfarms with 0.5° buffer."""
    from app.core.database import get_session_factory
    from app.models.windfarm import Windfarm
    from sqlalchemy import select

    AsyncSessionLocal = get_session_factory()
    async with AsyncSessionLocal() as db:
        result = await db.execute(
            select(Windfarm.lat, Windfarm.lng).where(
                Windfarm.lat.isnot(None), Windfarm.lng.isnot(None),
            )
        )
        coords = result.fetchall()
    if not coords:
        # Defensive default — global rather than Europe‑only
        return [85.0, -180.0, -85.0, 180.0]
    lats = [float(c.lat) for c in coords]
    lngs = [float(c.lng) for c in coords]
    return [max(lats) + 0.5, min(lngs) - 0.5, min(lats) - 0.5, max(lngs) + 0.5]

# In _download_era5_grib, replace the hardcoded line:
- 'area': [71, -11, 35, 32],  # N, W, S, E - covers Europe
+ 'area': await self._compute_windfarm_bbox(),

Update fetch_daily_all_windfarms.py to call the same helper (or duplicate the same logic and add a comment pointing to the canonical helper). Delete the inline inline bbox calculation in the script.

Fix C (defensive) — CHECK constraint to fail loud on regressions

Alembic migration:

# alembic/versions/<new>_weather_data_no_nan.py
def upgrade():
    op.execute("""
        ALTER TABLE weather_data
        ADD CONSTRAINT chk_weather_no_nan
        CHECK (
            wind_speed_100m = wind_speed_100m       -- NaN != NaN
            AND wind_direction_deg = wind_direction_deg
            AND temperature_2m_k = temperature_2m_k
        ) NOT VALID;
    """)
    # NOT VALID = applies to new inserts only; existing NaN rows survive
    # until cleanup. Deliberate — we drop them in step 3 separately.

def downgrade():
    op.execute("ALTER TABLE weather_data DROP CONSTRAINT chk_weather_no_nan;")

5.2 Aggregated‑data outliers

Some upstream sources (e.g. EIA for Block Island, South Fork) write daily/monthly totals into the hourly generation_data.hour column. Block Island (30 MW) shows 13,764 MWh / day — 458× rated capacity. The plausibility filter discards these but they indicate broken upstream data.

Detection query:

SELECT
    g.windfarm_id, w.name, w.nameplate_capacity_mw AS rated_mw,
    g.hour, SUM(g.generation_mwh) AS hourly_mwh,
    SUM(g.generation_mwh) / w.nameplate_capacity_mw AS multiplier
FROM generation_data g
JOIN windfarms w ON w.id = g.windfarm_id
WHERE g.generation_mwh IS NOT NULL AND w.nameplate_capacity_mw > 0
GROUP BY g.windfarm_id, w.name, w.nameplate_capacity_mw, g.hour
HAVING SUM(g.generation_mwh) > 1.5 * w.nameplate_capacity_mw
ORDER BY multiplier DESC LIMIT 50;

Triage upstream — this is most likely an EIA importer issue (app/services/eia_client.py). Track in a separate ticket.

6. P3 71 insufficient‑data windfarms

Definition of done: >1,400 of the 1,468 windfarms have power curves and at least one performance summary; the 71 insufficient‑data windfarms have a documented re‑run cadence; cron is running; CHECK constraint is in place to prevent regression.
Risks & mitigations:
  • CDS API throttling on bulk re‑import — mitigate with day‑by‑day batching and a 4‑concurrent cap.
  • Long delete on weather_data — 98M rows; do in a maintenance window or chunk by year (WHERE EXTRACT(YEAR FROM hour) = N) to avoid lock timeouts.
  • CHECK NOT VALID deliberately doesn't validate existing rows — if you'd rather block‑then‑cleanup, drop NOT VALID and run cleanup first.
  • Partial re‑import — if a region's re‑import is interrupted, force_refresh=False ensures resume picks up only missing days, not duplicates.
